Generate the specification for an application that has the following requirements:

-A webapi interface, that allows for running actions on the backend
-A backend action runner that can run multiple actions in parallel
-Each action registers its start, status, completion, and output with the runner.  Each is written to a log, and can be queried from the webapi interface.
-An action can initiate another action.
-The output of an action can be stored in a document storage on disk, and can be loaded as input to other actions.

The specification should be detailed, and break down the implementation into individual tasks with clear descriptions of what to implement.



---------------


Update the spec to define the following actions:

-SpecGenerator - Intended to generate full application specification.  Takes a rough specification requirements as input, sends the input to a llm model api endpoint to generate a full specification, and stores the results as an output specification.
-SpecUpdator - Intended to update application specifications with change requests from the user.  Takes a previously stored spec from the output storage and a refinement to apply, sends both to an llm model api endpoint to update the specification, and stores the results as an output specification.
-TaskEnumerator - Intended to break down a specification into a list of discrete tasks that can be implemented by an LLM.  Takes a previously stored spec from the output storage, sends a request to an llm api endpoint to break the specification down into a list of detailed task instructions, and stores the result as an output task list.
-TaskListImplementor - Intended to iterate over each of the tasks generated from a TaskEnumerator.  Takes a previously stored task list, and starts a TaskImplementor for each task in the list.
-TaskImplementor - Intended to request code from an LLM to implement a task.  Takes a task description as input, sends a request to an llm api endpoint to generate the code for that task, and stores the result to both the output directory, and to a project source directory.
-UnitTestEnumerator - Intended to use an LLM to analyze a source code file and specification to generate a list of instructions for unit tests to verify the source code.  Takes a source code file and task instruction for that source code file as input, sends a request to an llm api endpoint to generate instructions for implementing a complete set of unit tests to verify the source code, and stores the result to the output directory.
-UnitTestImplementor - Intended to take the instructions for a unit test generated by UnitTestEnumerator and use an LLM to generate the source code for the unit test.  Takes a previously generated unit test requirement as input, sends a request to an llm api endpoint to generate a unit test to verify the code is implemented correctly, and stores the result to both the output directory, and to the project source directory.
-CodeUpdator - Intended to update source code previously generated by TaskImplementor with change requests from the user.  Takes a source code file and a refinement to apply, sends both to an llm api endpoint to update the source code, and stores the result to both the output directory and to a project source directory.


------------



Given the specification, generate a list of explicit tasks to implement.  Each listed task should have the following qualities:

-Detailed enough that code can be generated by an LLM using the task description.
-Include details of how it connects to the other components of the application.
-The task should describe a single implemementation.  If multiple implementations are required to achieve a task, the task should be broken into multiple sub tasks.
