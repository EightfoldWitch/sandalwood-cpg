# 1. Backend: Action Runner (Expanded)

## 1.1 New Defined Actions

Each Action is a **specific type** that can be started manually, triggered automatically, or chained.

| Action Type | Description |
|-------------|-------------|
| **SpecGenerator** | Generates a full specification from a rough input using an LLM. |
| **SpecUpdator** | Updates an existing spec based on refinement input using an LLM. |
| **TaskEnumerator** | Breaks down a spec into a list of discrete tasks using an LLM. |
| **TaskListImplementor** | For each task in a task list, spawns a **TaskImplementor** action. |
| **TaskImplementor** | Requests LLM to generate source code for a task. |
| **UnitTestEnumerator** | Generates unit test instructions for a source code file and task spec. |
| **UnitTestImplementor** | Creates unit test source code based on instructions. |
| **CodeUpdator** | Updates existing source code with user refinements via LLM. |

---

## 1.2 Action Input/Output Behavior

| Action Type | Input | Sends to LLM | Output Saved To |
|-------------|-------|--------------|-----------------|
| SpecGenerator | Rough specification text | Yes (generate spec) | Output spec file (`outputs/spec_{id}.json`) |
| SpecUpdator | Existing spec + refinement | Yes (update spec) | Output spec file (`outputs/spec_update_{id}.json`) |
| TaskEnumerator | Specification | Yes (task breakdown) | Output task list (`outputs/tasks_{id}.json`) |
| TaskListImplementor | Task list | No (spawns actions) | Child action results |
| TaskImplementor | Task description | Yes (generate code) | Source file + output copy |
| UnitTestEnumerator | Source code + task instruction | Yes (generate test plan) | Output test instructions (`outputs/unittests_{id}.json`) |
| UnitTestImplementor | Unit test instruction | Yes (generate test code) | Test source file + output copy |
| CodeUpdator | Source file + refinement | Yes (update code) | Updated source file + output copy |

---

## 1.3 LLM API Interaction

All LLM interactions will be handled via a standard API client.  
The API client:
- Sends prompts to the LLM endpoint.
- Receives structured outputs (specifications, task lists, code, test instructions).
- Handles retries on failure.

### Example API Payload
```json
{
  "prompt": "Generate a full detailed application specification from this rough description: ..."
}
```

### Example Response
```json
{
  "response": "Full specification text..."
}
```

# 2. Backend: WebAPI (Updated)

## 2.1 Additional WebAPI Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/actions/start` | POST | Start an action, specifying the action type and input document or data. |
| `/api/actions/{id}/stop` | POST | Stop a specific action. |
| `/api/actions/stop-all` | POST | Stop all running actions. |
| `/api/actions/live` | GET | Fetch live running actions with parent/child relationship. |
| `/api/actions/history` | GET | Fetch history of completed, failed, or stopped actions. |
| `/api/files/output/{id}` | GET | Download an output or result file. |

# 8. Example Action Flow

**User Story:**
1. User provides a rough idea: "I want a todo list app."
2. User starts a **SpecGenerator** action.
3. Once complete, user reviews the generated spec.
4. User runs **TaskEnumerator** to break it into tasks.
5. User runs **TaskListImplementor** to auto-generate the app code!
6. User uses **UnitTestEnumerator** + **UnitTestImplementor** to generate tests.
7. If needed, user applies a refinement using **SpecUpdator** or **CodeUpdator**.
